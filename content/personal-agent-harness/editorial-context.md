# 编辑上下文

## 文章目标与组织

面向小红书读者，分享 personal agent 怎样持续接住被交出去的事情，以及 harness 需要处理的执行问题。开篇以 Instinct 的使用经历为例；正文拆 Grok Bot、Muse/Hatch 和 dots 所用的 Codex harness 三个实现，材料来自公开访谈、文档、文章及相关代码。语气自然，不写成规格书或研究报告。

保留三个大章节：

1. 从对话窗口，到长期助手。以 Kevin Rose 在 Tim Ferriss 访谈里讲的 Instinct 使用经历开场（只讲使用感受，不展开内部实现），接着保留与常见 thread 产品心智的对比，以及“长期助手要满足的四个要求”独立小节。
2. 三个案例，怎样把事情接着做。开篇先用一张对照表（列为执行中的新输入 / 提醒 / 恢复 / 调度；三行分别为 Grok Bot、Muse/Hatch、Codex（dots 的 harness 层）；“—”表示本文没有分析对应实现），再分别展开 Grok Bot、Muse/Hatch、Codex（dots 的 harness 层）三个案例。Instinct 不再作为案例之一。
3. 自己搭 harness 时，我会先想清楚什么。涵盖背景、进度、memory、上下文压缩、打断与恢复、权限、通知与调度之间的关系。

正文在第 01 章之前先用一段预告概述全文，再给出论点：同一个 session 里，模型大多沿着一条线推理；执行中的新输入，常见处理是排队到下一轮、在当前 turn 的安全点插入（steer），或直接打断。Codex 和 Claude Code 已经这样做，也能把长命令和子任务放到后台；把工作拆成能单独寻址的单元，等待会缩到具体步骤，但会多出协调工作。

收尾保留 BoAI 自我介绍、下一篇基于 pi coding agent 从 0 到 1 搭建 personal agent 的预告和自然的关注提示。来源部分开头保留一行证据说明：代码和二进制材料只做了阅读，没有对着线上产品运行；测试只是读了定义，没有执行。

## 不要在润色中丢掉的内容

- 四个要求是既定结构，不因追求自然行文而删除或打散：持续在场、快速响应、少让用户操心、主动发现下一步。
- thread 对比说的是默认围绕单项任务的产品心智，不是断言 thread 在技术上不能记忆、并行或 steer。
- 第一章采用“用 personal agent，最吸引我的地方是能把事情交出去。”不要改回“做 personal agent”。
- 第一章用隔几天继续项目、记得已有决定并跟上新进展说明体验；避免把 memory 术语生硬塞进体验描述。这不是全文禁用 memory。
- 实时转向不能只靠一个“先别发”的例子来证明；保留各案例可支持的具体机制及条件，不虚构独有能力。
- 不要写成“以前的 harness 把所有事都串在一条线上”，也不要写成新输入“只能等或被打断”；要写出 steer 这条路径。
- 四个词要分开：排队（排到下一轮）/ 插入当前 turn（steer）/ 抢占 / 打断（用户中止当前 turn）。
- Codex 是 session 中心的 harness，本身已经拆出部分工作（steer、后台终端、cell）；dots 建立在它之上，不能拿 Codex 当 session 中心 harness 的反例。
- Muse/Hatch 的重新入队是合并新旧输入、重新跑一遍，不是把工作拆开。
- 产品名统一写“Grok Bot”，不单独写“Grok”。
- “会话”指对话；exec 进程用“进程 ID（session_id）”。
- 对文章里某句文字的批评只修改该处，不擅自扩大为重构主题或删除整段结构。

## 证据与措辞

- Instinct 访谈是使用经历，不能当作内部 memory 或调度架构的证据。
- Grok Bot 使用非官方重建资料；Muse/Hatch 的具体实现来自非官方二进制归档，不能宣称线上验证。
- Grok Bot 的队列和优先级细节来自非官方重建代码；〔2〕只是来源与范围说明，不能把机制归到〔2〕本身。
- 没有可核对的代码位置，不新增 Grok Bot 的事实。
- 任何新增事实都要在正文“来源”和 sources.md 里有对应条目与 URL。
- 正文介绍 dots，并在正文中说明其基于开源 Codex harness 的公开署名来源。分析 Codex 源码不等于还原 dots 全部线上实现。
- 区分源码可见事实、经验描述和自己的工程判断。没有执行过的测试只能写成测试定义阅读。
- 调度优先级不等于授权；取消推理不等于撤销工具副作用；记下未来安排不等于已经设置调度。
- 不堆一整块泛泛的“资料说明”，把必要的范围限定放到对应案例。出处应能由读者找到，保留标题、作者/仓库、日期、固定版本与路径。

## 文风与排版

- 读起来像在分享自己想明白的事，不机械下定义，不堆术语，也不编造亲身使用经历。
- 改稿后整体通读，检查段落衔接，不只替换局部词语。
- 空白可以用有价值的说明或合适的图补足，但不要为了填满而加废话，也不要把字号放大掩盖内容不足。
- 历史版式正文为 10.5px、行高 1.5；CSS 画布 360 × 600，导出 1440 × 2400。新版本需要重新分页，不应强行锁定历史 11 页。
- 插图使用生图工具，不手搓插画；正文正常排版即可。
- 封面保留“以 Instinct、Grok Bot、Muse 和 dots 为例”的自然简介，不写“4 张图”或阅读时间营销字样。
- 来源索引与 BoAI 介绍、下期提示合并为结尾，避免另外一页只有收尾内容。
- 图片交付时按顺序逐张发送，不报张数、不加逐张编号说明。
